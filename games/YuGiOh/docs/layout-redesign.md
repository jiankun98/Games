# 游戏王 3D · 整体布局（Layout）改造调研

> 前提：保留 3D 对场与既有功能；只重排 DOM 层各区块的空间关系，让布局向真实卡牌游戏（Master Duel / 炉石 / MTG Arena）的屏幕组织方式靠拢。

## 一、现状结构（flex 纵向堆叠）

```
┌──────────────────────────────────────────────────────────┐
│ header 44px：主页 · 标题 · [第N回合·你的回合·主要阶段1] · 按钮组 │
├──────────────────────────────────────────────────────────┤
│ AI LP 条（全宽 × 40px）                                     │
├──────────────────────────────────────────────────────────┤
│                3D 舞台（flex:1，约 66% 高）                 │
│   hint3d(左上)  [卡牌预览(左中)]  [视角切换(左下)]            │
├──────────────────────────────────────────────────────────┤
│ 玩家 LP 条（全宽 × 40px）                                   │
├──────────────────────────────────────────────────────────┤
│ 回合条 52px：阶段提示(248px) + 进度条 + [进入战斗] [结束回合]   │
└──────────────────────────────────────────────────────────┘
   日志面板：底部全宽滑入；事件通知：顶部中央（header 下）
```

## 二、问题诊断（按影响排序）

1. **纵向空间被四层 DOM 行切割**：header 44 + AI LP 40 + 玩家 LP 40 + 回合条 52 ≈ 184px（约 20% 屏高）被 2D 行占用。LP 是全宽条但信息只占一半宽度——两侧全是死空间；更关键的是 **3D 场地与屏幕边缘被隔断**，玩家手牌（3D 场景底部）与屏幕底缘之间隔着两条横条，"我站在桌子前"的沉浸感被打破。
2. **LP 与"玩家身份"弱关联**：两条全宽条 + 名字分居两端，视线要在屏幕对角跳。真实游戏把 LP 做成**对角玩家盒**：对方盒右上、我方盒左下（MD 支持自定义浮动，炉石/MTGA 同为对角头像框），盒子聚合 名字 + LP + 卡组余量 + 墓地数，紧贴各自半场。
3. **回合信息三处重复**：header 的 phase-tag、回合条的 tb-tip、阶段进度条——同一信息写三遍，且回合条因此被撑到 52px 高。
4. **操作按钮离注意力中心远**：进入战斗/结束回合在最底部回合条里；玩家实际视线在 3D 场上的手牌与怪兽。MD 把阶段操作放右缘竖排，紧邻视线落点。
5. **左缘过载、右缘空置**：卡牌预览（左中）+ 视角切换（左下）+ 操作提示（左上）全挤在左边缘；右侧只有日志滑入。左右失衡。
6. **卡组/墓地余量缺结构化呈现**：3D 场里"卡组 55"小标签字小、无双方对照。

## 三、目标布局（对角玩家盒 + 满铺 3D + 右缘功能列）

```
┌────────────────────────────────────────────────────────────┐
│ ← 主页  游戏王·决斗3D   [第7回合·你的回合·主要阶段1]   ⚙ 🔊 📜 ? 新对局 │
├────────────────────────────────────────────────────────────┤
│                                        ┌──────────┐         │
│                 (AI 半场)              │ 阶段轨道  │         │
│                                        │ 抽·准·主1 │         │
│                                        │ 战·主2·终 │         │
│ ┌───────────────┐                      └──────────┘         │
│ │ AI 盒：AI      │                                           │
│ │ ◆LP ████████  │        [卡牌预览大图]                      │
│ │ 卡组53 · 墓地2 │        [召唤展示/横幅居中]                  │
│ └───────────────┘                                           │
│                                                             │
│                    (玩家半场 + 手牌)                          │
│                                                             │
│ ┌───────────────┐                      ┌──────────────────┐ │
│ │ 玩家盒：玩家    │                      │ ⚔ 进入战斗 (B)    │ │
│ │ ◆LP ████████  │                      │ ▶ 结束回合 (P)    │ │
│ │ 卡组48 · 墓地5 │                      └──────────────────┘ │
│ └───────────────┘                     [视角切换(竖排,小)]     │
└────────────────────────────────────────────────────────────┘
     事件通知/连锁横幅：顶部中央（维持现状）· 日志：右侧滑入
```

要点：
- **3D 满铺**：去掉两条全宽 LP 行与 52px 回合条，3D 舞台从 ~66% 高提到 ~89%（header 之外全屏）。手牌直接贴屏幕底缘，沉浸感恢复
- **对角玩家盒**（absolute 悬浮，半透明玻璃）：AI 盒右上、玩家盒左下；盒内 LP 条沿用现有 2.0 斜切金属样式，新增 卡组余量/墓地数（数据 `state.x.deck.length / graveyard.length` 现成）
- **阶段轨道右缘竖排**（MD 式）：6 节点从回合条里迁出，`fixed right:14px top:50%` 竖排；回合条整体删除
- **操作按钮簇右下**：进入战斗/结束回合浮在手牌右上侧，保留快捷键角标；不可用时灰化（沿用现有渲染逻辑）
- **回合信息收敛到 header 一处**：phase-tag 保留；tb-tip 的提示文案并入按钮 title 与 hint3d
- **视角切换移到右下**（与左上预览对角平衡），尺寸缩小
- **hint3d 移到舞台底部中央**（改浮动小条），贴近手牌操作区
- **日志面板**从底部全宽改为右侧滑入抽屉（宽 ~380px，避开右缘阶段轨道时自动下移）

## 四、实施影响面（已核对引用）

| 改动 | 影响文件 | 风险 |
|---|---|---|
| LP 行 flex 移除 → 盒子 absolute | game3d.html 结构、game3d.css；hud 中 `lp-row-me/ai` 的 id 保留（render 继续点亮） | 低 |
| 玩家盒聚合卡组/墓地数 | hud render 新增两个数字更新（state 已有） | 低 |
| 回合条删除 → 按钮簇 + 阶段轨道迁移 | main.mjs 的 `$("tb-main"/"tb-end"/"tb-tip")` 绑定改新 id；phase-track 选择器不变 | 中（id 迁移需仔细） |
| tb-tip 移除 | renderTurnBar 中 tip 文案逻辑并入按钮 label/(title) | 中 |
| 视角切换/hint3d/日志移位 | 纯 CSS（position 调整） | 低 |
| mod-bar/atk-overlay 底部偏移重校 | 纯 CSS | 低 |

## 五、建议

一次性做布局重排（B/C 演出与美化已就位，不受影响），预计改动集中在 game3d.html（结构）+ game3d.css（定位）+ hud.mjs/main.mjs（少量 id/渲染迁移）。完成后配合现有演出层，整体观感即对齐 Master Duel 的屏幕组织。
